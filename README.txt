PIPETWIN
Прогноз минимальной остаточной толщины стенки трубопровода
Финальная версия: H18 для S1, H31 исключительно для S2
Дата фиксации: 16.11.2026
==============================================================================

1. НАЗНАЧЕНИЕ И ГОТОВЫЙ РЕЗУЛЬТАТ

PipeTwin решает задачу регрессии из кейса Nedra Digital: для каждого 10-метрового
сегмента трубы прогнозирует минимум остаточной толщины стенки на заданную дату.
Прогноз выражен в миллиметрах. Одна строка результата соответствует одному
сегменту, а не отдельному дефекту, точечному замеру УЗТ или скорости коррозии.

Прогнозируемые трубы:

  S1: id=1250022871; дата 01.12.2023; между ВТД.
      Длина 5248,4 м; номинальная толщина 8,0 мм.
      Последний доступный ВТД: 06.07.2022; горизонт 513 дней.
      525 сегментов: segment_id от 0 до 524.

  S2: id=1250009583; дата 01.07.2022; от ввода до первого ВТД.
      Длина 14745,1 м; номинальная толщина 4,5 мм.
      Ввод: 20.06.1993; горизонт около 29,029 года.
      1475 сегментов: segment_id от 0 до 1474.
      Собственные ВТД и УЗТ этой трубы не используются.

Готовый файл для сдачи:
  production/h18_h31_verified/result.csv

Файл содержит заголовок и ровно 2000 строк данных. Формат:
  id,segment_id,thickness_pred

Разделитель столбцов - запятая, десятичный разделитель - точка, кодировка UTF-8.
Индекс DataFrame, дата, диагностические флаги и дополнительные столбцы в CSV
для оценки не включаются. Дата однозначно определяется заданным кейсом.

SHA-256 зафиксированного result.csv:
  5fb9bf836c0b9423b0ce33be58d5235866a3bc74a0549c975b37098112011d68

Модели находятся в production/h18_h31_verified_models/. Для использования
готового результата запуск обучения не требуется.


2. ТРЕБОВАНИЯ К СРЕДЕ И УСТАНОВКА

Проверенная среда: Windows 11, CPython 3.12.8, CPU. GPU, облачные API, доступ
к закрытым сервисам и сетевые запросы при расчёте не требуются. Интернет нужен
только при первоначальной установке Python-пакетов, если их нет локально.

Основной файл зависимостей - requirements.txt. Он подключает
requirements-next.txt с версиями финального ML-решения и фиксирует остальные
необходимые зависимости. scikit-learn для сохранённых моделей: строго 1.7.2.
Старое окружение .venv с другой версией scikit-learn не используйте для загрузки
этих артефактов.

Все команды ниже выполняются из корня проекта. На проверенном ПК это:
  C:/Program Files/PipeTwin

Установка в отдельное окружение, PowerShell:

  py -3.12 -m venv .venv_submission
  .\.venv_submission\Scripts\python.exe -m pip install -r requirements.txt
  $python = (Resolve-Path '.venv_submission/Scripts/python.exe').Path
  $env:PYTHONHASHSEED = '17'

Активация окружения не обязательна: команды явно используют его Python.
Для запуска в другой ОС создайте venv на Python 3.12 и выполните те же модули
через python. Синтаксис PowerShell и пути к локальному окружению относятся
к Windows; проверка этой поставки выполнена именно на Windows CPU.

Seed исследования - 17. Финальные Ridge и Gaussian process вычисляются
детерминированно, без случайного разделения данных и случайной инициализации.
Дополнительного параметра --seed у production CLI нет.

Для быстрого запуска на исходном ПК вместо создания окружения можно задать:

  $python = 'C:/Users/Администратор/Documents/PipeTwin_s1abc_env/Scripts/python.exe'
  $env:PYTHONHASHSEED = '17'


3. ПОЛНОЕ ВОСПРОИЗВЕДЕНИЕ ИЗ ИСХОДНЫХ CSV

Это основной маршрут проверки решения: исходные CSV -> подготовка данных ->
обучение -> прогноз -> result.csv. Он не требует существования scratch-папок
с прежними подготовленными данными или абсолютных путей к чужому компьютеру.

В каталоге data/ должны находиться шесть исходных файлов:

  passport.csv
      Паспорт: идентификаторы, длина, диаметр, номинальная толщина, дата ввода.
  profile.csv
      Дистанция и высота трассы.
  vtd.csv
      История обследований, остаточная толщина и характеристики дефектов.
  uzt.csv
      Точечная ультразвуковая толщинометрия.
  regime.csv
      В фактической выгрузке это коррозионный мониторинг, не суточный Techmod.
  tech_mode_for_embedings_with_length_with_temperatures_ids16.csv
      Фактический источник технологического режима, температуры и скоростей.

Назначение источника определяется по схеме столбцов, а не только по имени.
Не переименовывайте файл мониторинга в технологический режим: это разные данные.

Команды PowerShell после установки зависимостей и определения $python:

  & $python -B -m src.data_prep --data-dir data --config configs/production_preprocessing.json --output-root scratch/submission_data

  & $python -B -m src.ml.production train --data-root scratch/submission_data --config configs/production_forecast.json --output-root production/submission_models

  & $python -B -m src.ml.production predict --data-root scratch/submission_data --model-root production/submission_models --output-root production/submission_forecast

Полученный результат:
  production/submission_forecast/result.csv

При необходимости положить сдаваемый CSV рядом с README:
  Copy-Item -LiteralPath 'production/submission_forecast/result.csv' -Destination 'result.csv'

Папки production/submission_models и production/submission_forecast должны быть
новыми: train/predict отклоняют существующую выходную папку. При повторении
выберите другие имена и последовательно замените их во всех командах.
Подготовку данных также рекомендуется выполнять в новую scratch-папку.

Конфигурация configs/production_forecast.json содержит ссылку на
experiments/incremental_cycle/e0/result.csv. Этот файл должен входить в поставку:
он нужен только для копии старого результата и сравнения baseline, а не как
признак, обучающий ответ или источник предсказаний выбранных H18/H31.

Конфигурация подготовки сохраняет также дополнительные таблицы привязки
одометра из исследовательского контура. Итоговая H18 использует исходный
Distance; скрытое включение нового исправления координат не производится.


4. БЫСТРЫЙ ПРОГНОЗ ИЗ СОХРАНЁННЫХ МОДЕЛЕЙ

Если data preparation и обучение уже выполнены, достаточно одной команды:

  & $python -B -m src.ml.production predict --data-root scratch/odo_alignment_verified --model-root production/h18_h31_verified_models --output-root production/submission_replay

Выход: production/submission_replay/result.csv. Чтение обучающих ответов из
processed/training_targets и переобучение моделей этому маршруту не нужны.
Используются сохранённые preprocessing и коэффициенты из модельного комплекта.

Проверка контрольной суммы в PowerShell:

  (Get-FileHash -Algorithm SHA256 -LiteralPath 'production/submission_replay/result.csv').Hash

Ожидается SHA-256 из раздела 1. Полный повтор из исходных CSV и повторная
загрузка моделей проверяются отдельно: совпадение только числа строк не
считается подтверждением совпадения прогнозов.


5. ЧТО ДЕЛАЕТ КАЖДЫЙ ЭТАП

5.1. Чтение и нормализация.
Модуль src.data_prep определяет типы источников, кодировку и разделители,
приводит имена полей, числа, идентификаторы и даты к единой схеме. Сохраняются
номер исходной записи, причины отказов и SHA-256. Повреждённое значение не
превращается автоматически в ноль.

5.2. Контроль качества и построение целей.
Проверяются единицы, координаты, паспортные ограничения и даты. Для каждого
сегмента и кампании ответом служит минимум допустимых измеренных остаточных
толщин ВТД. Глубина дефекта, паспортный номинал и точечный УЗТ не подменяют
этот ответ. Правила исключения перечислены в разделе 6.

5.3. Сегментация и пространственная привязка.
Сетка строится по полной паспортной длине с шагом 10 м. Для 0 <= x < L:
  segment_id = floor(x / 10).
Интервалы полуоткрытые: [0,10), [10,20), ... . Последний сегмент может быть
короче 10 м. Точка ровно на конце трубы L относится к последнему сегменту.
Для S1 последний интервал: [5240; 5248,4] м; для S2: [14740; 14745,1] м.
Высоты интерполируются по профилю; уклон делится на фактическую дистанцию.

5.4. Построение признаков на дату.
Для каждого примера берётся отдельный исторический срез. Динамические данные
и прошлые измерения должны иметь дату строго меньше даты прогноза. Вместе
с агрегатами сохраняются покрытие истории и пропуски. Для S2 собственные ВТД
и УЗТ целевой трубы исключены независимо от наличия таких строк в архиве.

5.5. Обучение.
Команда train обучает отдельные ветви S1 и S2, их scaler/imputer и контрольные
модели. Признаки нормируются только по обучающим данным. Результат - комплект
forecast_models.joblib, manifest.json и training_keys.csv.
Полностью пустые и константные признаки исключаются по train; параметры
заполнения, масштабирования и список использованных признаков сохраняются.

5.6. Прогноз и экспорт.
Команда predict загружает комплект, строит полную целевую сетку, применяет
H18 к S1 и H31 к S2, проверяет ключи и физические границы. Результаты сохраняются
в новую папку после успешной проверки. Итог ограничен интервалом [0; номинал].


6. ПРАВИЛА ОЧИСТКИ ДАННЫХ И ПРИНЯТЫЕ ДОПУЩЕНИЯ

6.1. Форматы и пропуски.
Поддерживаются исходные UTF-8/Windows-1251, десятичная запятая и стандартные
числовые разделители. Неоднозначные даты, цензурированные и неразбираемые
числа отмечаются отдельно. Неизвестные значения остаются пропусками;
их заполнение для модели выполняется train-only imputer. Несогласованные
копии одного источника не выбираются молча.

6.2. Паспорт и единицы.
В паспорте требуется один уникальный ID, положительные длина, диаметр и номинал.
Длина в километрах умножается на 1000. Диаметр Techmod переводится из метров
в миллиметры только при согласовании с паспортом. Обводнённость хранится
в процентах, а её физическая доля вычисляется делением на 100.
Для кампании ВТД 23.09.2018 глубина переводится из долей в проценты только
после проверки согласованности с измеренной остаточной толщиной. Эта операция
не пересчитывает саму измеренную остаточную толщину.

6.3. Координаты.
Используется Distance, не Distance Raw. Координата трактуется локально для
данного ID. Отрицательные дистанции, дистанции за пределами длины и записи
без ключа отправляются в карантин. Их не прижимают к нулю или концу трубы
и не возвращают в модель подбором сдвига по проверяемым ответам.

6.4. Профиль трассы.
Точные дубли удаляются. Противоречащие друг другу высоты в одной координате
требуют разрешения конфликта и останавливают расчёт. На границах, не покрытых
профилем, используется крайняя известная высота с флагом экстраполяции.
Резкий перепад отмечается в аудите, а не автоматически удаляется как дефект.

6.5. Остаточная толщина ВТД.
Для целевой толщины исключаются неположительные значения, отсутствие
разрешённого номинала и значения выше паспортного номинала более чем на 0,02 мм.
Измерения до ввода трубы и скрытые/будущие целевые кампании не допускаются
как обучающие ответы. Исходные строки и причины исключения сохраняются.
Несовпадение с локальной wall_thickness отмечается отдельно и не вводит
второй, неоговорённый порог вместо паспортного номинала.
Швы не исключаются автоматически по текстовому описанию. Нет правила
«оставить только удобные дефекты», улучшающего состав проверяемых сегментов.

6.6. УЗТ.
Точечный УЗТ не равен минимуму 10-метрового сегмента. В доступной выгрузке
все 67 замеров превышают паспортный номинал и не используются как признаки
до подтверждения их трактовки. Они сохранены в данных и отчёте качества.
В сценарии S2 собственные замеры УЗТ запрещены в любом случае.

6.7. Аномалии технологического режима.
Сначала отсекается будущее, затем применяются проверки качества. Мягкая
аномалия сохраняется, если наблюдается не менее трёх последовательных
календарных дней; кратковременное сомнительное значение заменяется пропуском.
Несколько записей одних суток не считаются тремя днями. Физически недопустимые
значения, например отрицательный расход или обводнённость вне [0;100],
исключаются из признаков независимо от длительности.
Пороговые значения находятся в configs/production_preprocessing.json.
Это правила контроля данных, а не заявленные универсальные границы коррозии.

6.8. Редкий мониторинг и неизвестная история.
Химические данные присоединяются только при подтверждённой идентичности объекта
и допустимой дате. Фиктивное заполнение pH, CO2 и минерализации чужой трубы
не используется. Для целевых труб подтверждённые химические признаки отсутствуют.
Неизвестные единицы давления и вязкости не исправляются догадкой; число
Рейнольдса по неподтверждённой вязкости не рассчитывается. Осадок не моделируется.

История режима не покрывает весь срок эксплуатации S2. При интегрировании
разрешённое наблюдение переносится вперёд максимум на одни сутки, без переноса
назад. Оставшиеся годы в физической модели оцениваются по среднему воздействию
наблюдавшейся среды этой же трубы (own_mean). Это явно заданное допущение,
а не восстановленная фактическая история и не заполнение пропуска нулевой
коррозией. Номинал предполагается постоянным: подтверждённой карты вставок
и прошлых ремонтов, позволяющей задать локальную конструкцию, нет.

6.9. Пропуски прошлого ВТД в S1.
Для H18 из последнего прошлого ВТД доступны прямые значения в 508 сегментах.
В остальных 17 используется резервная база h0 из исторического среза;
дополнительная поправка H18 на этих сегментах равна нулю. Резервное значение
не объявляется измерением. Прогноз может оказаться выше предыдущего минимума:
модель учитывает различие измеренных минимумов, а не утверждает рост металла.

Отчёты каждого запуска подготовки находятся в <data-root>/reports/:
  source_inventory.json       - распознанные источники и схемы;
  unit_resolution.json        - правила единиц и преобразования;
  row_reconciliation.json     - учёт сохранённых и исключённых строк;
  data_quality.md             - сводка качества и ограничений;
  leakage_audit.json          - временные ограничения и запреты S2;
  run_manifest.json           - конфигурация и контрольные суммы.
Отвергнутые записи и quality_issues сохраняются в <data-root>/processed/.


7. ИТОГОВЫЕ МОДЕЛИ И ФИЗИЧЕСКИЙ СМЫСЛ ПРИЗНАКОВ

S1 / H18: сохранить информативный профиль прошлого обследования и добавить
поправку по геометрии и типам ранее наблюдавшихся дефектов.

  b = смесь 50/50 минимума и 5-го процентиля прошлого ВТД;
      процентиль приведён к среднему и разбросу минимума на полной сетке.
  delta = Ridge(базовые признаки + H18) - Ridge(базовые признаки).
  prediction = clip(b + delta, 0, nominal_thickness_mm).

Поправка добавляется только на прямых прошлых замерах. Обе Ridge используют
alpha=10 и равный суммарный вес простых участков. Дополнительные признаки:
log1p длины и ширины дефекта, разность медианы и минимума, междецильный размах
толщин, доли записей потери металла и внешних дефектов. Базовые признаки
описывают прошлую толщину, её давность, соседние замеры, положение и рельеф.
Угол дефекта не используется. Обучение - 357 допустимых исторических пар.

Размеры и распределение прошлых дефектов описывают устойчивость локального
минимума: единичная тонкая точка и протяжённая зона могут переноситься
на следующий ВТД по-разному. Это статистическая интерпретация признаков,
не доказанная причинная модель изменения металла.

Для целевого S1 используется опубликованный Distance. Карты привязки ВТД
2022 года, подтверждённой до 01.12.2023, нет. Возможность передать такую карту
через --verified-s1-anchors описана в docs/production_forecast.md.

S2 / H31: физический средний уровень + переносимая пространственная поправка.

  physics = clip(номинал - r_ref * эффективная экспозиция, 0, номинал).
  prediction = clip(physics + GP_shape - среднее GP_shape по длине, 0, номинал).

Средний уровень учитывает возраст, температуру, обводнённость и скорость;
неотрицательная опорная скорость r_ref обучается на разрешённых данных.
Заданные инженерные priors: theta=2500 K, beta_W=0,30, beta_v=0,10,
смещение скорости 0,10 м/с, степень возраста 1. Их не выдают за независимо
оценённые электрохимические константы.

Gaussian process обучается на центрированных остатках других труб.
Используются высота, уклон, его модуль, положение, локальная низина и глубина
впадины. Эти признаки позволяют менять форму прогноза вдоль трубы; рельеф
служит косвенным описанием условий потока и возможного удержания воды,
а не измерением самой коррозии.

Ковариация: линейная компонента + Matern 3/2 по положению, умноженный на RBF
по признакам. Фиксированные параметры H31:
  length_fraction=0.25; feature_length_per_sqrt_dimension=1.0;
  spatial_variance=4.0; noise_to_linear_variance=10.0.
Обучение - 372 первых измерения других участков от 23.09.2018, строго до
01.07.2022. Собственная диагностика целевого S2 не участвует ни в fit, ни в predict.

H31 применяется только к S2. Ветви не смешиваются; вес общего ансамбля
не подбирается. Нормировка S1 и центрирование S2 требуют полных сеток.
Не следует передавать в модели только отдельные «интересные» сегменты.


8. ВАЛИДАЦИЯ, ГОРИЗОНТЫ И СРАВНЕНИЕ С БАЗОЙ

Главная метрика задания:
  pearson_squared = corr(y_true, y_pred)^2.

Она рассчитывается отдельно по кейсам и профилям. Знак Pearson r сохраняется.
Обычный R2 = 1 - SSE/SST, MAE, RMSE, bias и MAPE считаются отдельно и не
подменяют конкурсную метрику. Для постоянных векторов и групп менее трёх
наблюдений корреляция показывается как undefined, а не заменяется нулём.

Основные повторные измерения на прежних development-разбиениях:

  S1: ретроспектива 06.07.2022 -> 01.12.2023, горизонт 513 дней, n=52.
      Frozen baseline joint_blend: Pearson r2 = 0.458021656.
      H18:                       Pearson r2 = 0.511492212.
      Изменение: +0.053470556; signed r = +0.715186837.

  S2: перенос к первому обследованию 12.08.2023, горизонт 11.811 года, n=94.
      Frozen baseline spatial_no_temperature_centered: r2 = 0.040831812.
      H31:                                            r2 = 0.059538166.
      Изменение: +0.018706355; signed r = +0.244004439.

  S2, дополнительная проверка: исключение участков кампании 23.09.2018,
      горизонт 18.420 года, n=372, фиксированные признаки basin_ranks.
      Baseline: r2 = 0.008760664; H31: r2 = 0.004031196.
      Изменение: -0.004729468; signed r H31 = +0.063491697.

Эти сводные r2 по объединённым участкам приведены для воспроизведения
истории эксперимента. Они не равны метрике скрытой целевой трубы. Полные
оценки каждой трубы/кампании, включая отрицательные r и undefined, сохранены:
  production/h18_h31_validation/metrics.csv
  production/h18_h31_validation/<scheme>/validation_predictions.csv
  production/h18_h31_validation/<scheme>/split_keys.csv

В S1 два связанных отложенных участка: 4 и 48 сегментов. Их r2:
  id=1250009490: baseline 0.262284 -> H18 0.292578;
  id=1250011604: baseline 0.466294 -> H18 0.483496.
Все они относятся к одной родительской трубе. В ретроспективе S2 семь
связанных участков, в том числе группы из 1, 3 и 4 точек. Отрицательный r
H31 есть на двух профилях; один профиль не имеет определённой корреляции.
H31 ухудшает дополнительную проверку 2018 года на всех трёх участках.

Вспомогательные ошибки на основных сводных development-наборах, мм:
  S1: MAE 0.372496 -> 0.493439; RMSE 0.467289 -> 0.575867.
  S2: MAE 0.314583 -> 0.333021; RMSE 0.458987 -> 0.464529.
Выбранные методы повышают основную сводную корреляцию, но не снижают эти
абсолютные ошибки. Все метрики, включая обычный R2 и MAPE, доступны в CSV.

Защита от утечки:
  - В S1 модель обучается на других простых участках с метками до cutoff;
    проверяемый участок исключён из fit. Геометрические опоры внутри
    проверяемого блока и буфера также исключаются.
  - Ретроспектива S1 использует опоры соседних труб на дату ответа. Это
    ограничение исследовательского дизайна, а не строго доступная заранее
    карта для целевой трубы.
  - В S2 train содержит только метки до 01.07.2022. При исключении участка
    его метки не участвуют в fit; собственная диагностика запрещена.
  - Imputer, scaler и коэффициенты обучаются только на train. Ключи и ответы
    сравниваются по id,segment_id,prediction_date, а не по порядку строк.

Исследованы H01-H40: рассмотрено 40, реализована и измерена 31 с учётом
диагностических проверок; у 13 остались ограничения, часть из них пересекается
с измеренными. Итоговое сравнение:
  experiments/r2_pool/final_comparison/report_ru.md
  experiments/r2_pool/final_comparison/registry_ru.md
Сохранены отрицательные результаты, простые базы и абляции. H12 остаётся
в исследовательском рейтинге, но в финальную сборку не включена.

Независимого финального holdout и ответов скрытого конкурса нет. Эти проверки
уже использовались при выборе методов; повторное воспроизведение не делает
их независимыми. На целевых горизонтах S1 и S2 оценка организатора неизвестна.
Особенно ограничен перенос S2 на 29-летний горизонт. Статус результата:
исследовательский локальный прирост на основной ретроспективе.


9. ПРАКТИЧЕСКОЕ ИСПОЛЬЗОВАНИЕ: ПРИОРИТЕТНЫЕ 10 %

Для первичной очереди проверки сегменты ранжируются отдельно внутри каждой
трубы по возрастанию thickness_pred. При равенстве выбирается меньший
segment_id. Количество - ceil(0.10 * число сегментов): 53 для S1 и 148 для S2.
Это очередь обследования по прогнозу, не вероятность отказа и не решение
о ремонте. Нормативная критическая толщина в исходных данных не задана.

Готовая очередь: reports/final_top10_segments.csv. Её можно воспроизвести
следующей командой PowerShell; она создаёт
reports/final_top10_segments.csv, не изменяя result.csv:

@'
from pathlib import Path
import math
import pandas as pd
f = pd.read_csv('production/h18_h31_verified/result.csv')
dates = {1250022871: '2023-12-01', 1250009583: '2022-07-01'}
lengths = {1250022871: 5248.4, 1250009583: 14745.1}
parts = []
for pid, g in f.groupby('id', sort=True):
    g = g.sort_values(['thickness_pred', 'segment_id']).head(math.ceil(len(g) * .1)).copy()
    g['prediction_date'] = dates[pid]
    g['priority_rank'] = range(1, len(g) + 1)
    g['start_m'] = g.segment_id * 10
    g['end_m'] = (g.start_m + 10).clip(upper=lengths[pid])
    parts.append(g)
Path('reports').mkdir(exist_ok=True)
pd.concat(parts, ignore_index=True).to_csv('reports/final_top10_segments.csv', index=False)
'@ | & $python -

При копировании here-string маркеры @' и '@ должны начинаться с начала строки
PowerShell, а строки Python должны сохранять свои внутренние отступы.
Калиброванные интервалы неопределённости для финальных прогнозов не заявлены:
на имеющихся независимых кампаниях их надёжность не подтверждена.


10. ПРОВЕРКИ КОРРЕКТНОСТИ И ВОСПРОИЗВОДИМОСТИ

В финализированной версии пройдено 197 тестов. Полный успешный лог:
  experiments/r2_pool/integration/h18_h31/test_results_verified.txt

Для повторения общего набора на данной исследовательской копии:

  $env:PIPETWIN_NEXT_DATA_ROOT = (Resolve-Path 'experiments/next_cycle/data_generation').Path
  & $python -B -m unittest discover -s tests -v

Некоторые прежние исследовательские тесты требуют именно этой подготовленной
копии с проверенными LF-файлами. Это зависимость общего архива тестов,
не требование к основному маршруту получения result.csv в разделе 3.
Компактные проверки интерфейса финального прогноза без этого архива:

  & $python -B -m unittest tests.test_production_forecast -v

При подготовке этого README полный расчёт заново из исходных CSV и отдельный
прогноз из сохранённых моделей дали тот же SHA-256, что и зафиксированный
result.csv. Повторная подготовка прошла 306 проверок и 29 CSV/Parquet-пар;
восемь компактных тестов финального интерфейса также пройдены.

Проверка сохранённых моделей, отсутствия переобучения и изоляции ветвей:

  & $python -B -m scripts.verify_production_forecast --data-root scratch/submission_data --model-root production/submission_models --forecast-root production/submission_forecast --output-root scratch/submission_reload_check

Она повторяет predict в новом процессе, запрещает fit и чтение обучающих
ответов, сравнивает result.csv побайтно, проверяет даты обучения, исключение
целевого S2, четыре абляции и точность копии предыдущего baseline.

Повторная оценка финальных реализаций на прежних замороженных разбиениях:

  & $python -B -m src.ml.production_validation --data-root scratch/submission_data --output-root production/submission_validation

Для этой команды нужен архив experiments/r2_pool с ключами, опорами и
исследовательскими прогнозами. Это дополнительная проверка, не основной predict.

Экспорт автоматически проверяет ровно три столбца, полноту и уникальность
целевых ключей, конечность чисел и диапазон толщины. Авторитетный
sample_result.csv в переданной выгрузке отсутствует: ключи сверяются с полной
сеткой из паспортных длин. Если шаблон организатора появится, его можно
передать в predict параметром --template для дополнительной сверки ключей.

12. ОТКАТ И ТИПОВЫЕ ПРОБЛЕМЫ

Для готового отката используйте previous_result.csv из папки финального
прогноза. Чтобы экспортировать обе прежние ветви из того же комплекта:

  & $python -B -m src.ml.production predict --data-root scratch/odo_alignment_verified --model-root production/h18_h31_verified_models --s1 baseline --s2 baseline --output-root production/rollback_run

Частые причины остановки:
  - FileExistsError: указана уже существующая папка моделей или прогноза.
    Задайте новую папку; исходные результаты не удаляйте.
  - Artifact checksum mismatch: входы изменились после подготовки.
    Перестройте данные из исходных CSV в отдельной папке.
  - Несовместимый pickle/scikit-learn: используется другое окружение.
    Установите зависимости из requirements.txt и используйте его Python.
  - Нет scratch/odo_alignment_verified: выполните полный маршрут раздела 3
    и передавайте созданный --data-root явно.
  - Нет прежнего result.csv: восстановите поставляемый
    experiments/incremental_cycle/e0/result.csv; не подменяйте его скрытым фактом.
  - Ошибка PIPETWIN_NEXT_DATA_ROOT при полном наборе тестов: задайте путь
    из раздела 10 или выполните компактный набор финальных проверок.

Источник требований к README: PDF кейса, раздел «Состав решения», пункт 3,
и PDF критериев оценивания, пункт 3. Запуск описан в разделах 2-4, этапы -
в разделе 5, правила очистки и допущения - в разделе 6. Разделы 7-12 раскрывают
модель, валидацию, практическое применение и проверку результата.
