# Решения после проверки исходников и резюме встречи

Документ фиксирует реализованные правила подготовки данных. Он не заменяет резюме встречи и не объявляет неустановленные причины аномалий фактами.

| Вопрос | Реализованное действие | Что остаётся неизвестным |
|---|---|---|
| Целевые ID и даты | 1250022871 / 01.12.2023; 1250009583 / 01.07.2022 | Время ВТД внутри дня, поэтому день T исключён целиком |
| Минимальная толщина | Минимум измеренного остатка по ID, дате и сегменту | Полное покрытие дефектоскопом: отсутствие записи не означает номинал |
| Масштаб глубины 2018 | Доля → проценты; правило проверяется по локальной стенке и остатку | Новые выгрузки с другим форматом должны отдельно подтверждать правило |
| Глубина в паспорте | Диагностические поля сохранены текстом, но не используются в модели | Семантика процента оставшейся толщины должна быть подтверждена до использования |
| Дистанции | ВТД использует Distance; точки вне [0,L] в карантин | Физическая причина выхода за границу не установлена |
| Точка ровно L | Последний сегмент; никакой дополнительной строки ответа | Правило сверить с организаторами, если появится настоящий шаблон |
| Длинный дефект | Привязка по указанной точке Distance | Не переносим минимум по всем пересекаемым сегментам без правила организаторов |
| Служебные строки и кластеры ВТД | Без измерения остатка не дают целевую метку; минимум не зависит от дублирования кластера | Число записей называется observation_count, не числом независимых дефектов |
| ВТД раньше ввода | Сохранить флаг, не допускать в training_targets, не исправлять дату | Замена, переоформление или ошибочная привязка |
| УЗТ выше номинала | Сохранить измерение, исключить из признаков, указать флаг | Методика и объект измерения |
| Мониторинг с конфликтом ID/направления | Не присоединять и не распространять медианы | Нужна подтверждённая таблица соответствий |
| Экспозиция образца | Сохранить заявленную и вычисленную длительность; несогласованные записи не использовать | Какая дата/длительность верна; скорость коррозии не пересчитывается |
| Плотность мониторинга 39/76/81 | Пометить подозрительной, не угадывать коэффициент единиц | Ошибка единицы или другого поля |
| Отрицательная защитная эффективность | Сохранить с информационным флагом | Может быть реальным измерением; автоматически не обнуляется |
| Нулевое давление/температура при потоке | Мягкая аномалия, фильтрация по правилу трёх дней, исходник сохранён | Может быть заглушкой; устойчивость не доказывает измерительную достоверность |
| Устойчивые выбросы | Сохранять после трёх последовательных наблюдаемых календарных дней до T | Сходство определяется одним правилом превышения порога, а не точным совпадением чисел |
| Единичный всплеск расхода | Маскировать также связанные q_oil и скорости в usable-полях | Численные пороги аудита — допущения, доступны в конфигурации |
| Несколько расчётов в день | Медиана пригодных значений за день | Реальная длительность каждого режима неизвестна |
| Будущая информация | Фильтр до T выполняется до временной очистки и агрегации | Дата доступности статических паспортных свойств не восстановима |
| Редкие физико-химические измерения | Только подтверждённая связь и дата снятия до T | Не переносятся на чужие трубы без обоснования |
| Профиль | Кусочно-линейная интерполяция; интеграл высоты по длине; фактический уклон | Ступени >1 м/м сохранены с флагом; точность геосъёмки неизвестна |

В папке `data/cleaned` находится полный архив нормализованных источников, а не готовая обучающая матрица. В ней намеренно есть будущие записи: для каждого среза они отбрасываются `build_features_asof`. Прямое усреднение полного архива снова создаст утечку будущего.

В `target_features` попадают только геометрия, явные статические поля, возраст без хронологических противоречий, проверенные на дату гидравлические агрегаты, доступная физико-химия и допустимые прошлые ВТД/УЗТ. `pit_corrosion_intensity`, диагностические итоги паспорта, текущие сведения об обслуживании и неустановленные свойства покрытия не используются.

Для обучения нужны отдельные разбиения по времени и трубам. Препроцессор не подтверждает независимость соседних сегментов и не подменяет проверку модели. Холодный старт исключает историю ВТД и УЗТ независимо от того, присутствует ли она в архиве.

## Дополнения аудита парсера (2026-11-15)

- ID простого участка разбирается как точное положительное целое Int64 без промежуточного float. Дробные и выходящие за диапазон ID отклоняются; неразбираемый текст сохраняется в журнале ошибок.
- До чтения таблицы проверяются уникальные непустые заголовки и число полей каждой логической CSV-записи. Кавычки и переносы внутри поля поддерживаются. `source_row` — номер логической записи с учётом заголовка, а не физической строки многострочного файла.
- Отсутствующая дата установки или снятия означает неизвестную экспозицию: `exposure_invalid_flag=True`. Такие записи остаются в архиве и не допускаются в признаки.
- Температура ≤ −273.15 °C всегда маскируется в usable-полях; повторяемость не отменяет физическое ограничение. Сырой источник сохраняется.
- Архивный `history_date_conflict_flag` паспорта не передаётся напрямую в признаки. Для `between_vtd` конфликт определяется только по ВТД до отсечения; для `cold_start` диагностическая история не влияет ни на флаг, ни на возраст.
- CSV сохраняет доли секунды до наносекунд. Формат даты может быть `YYYY-MM-DD` или с пробелом перед временем; потребители должны разбирать ISO-совместимую дату, а не фиксированную строку. Int64 проверяется точно; для вещественных значений действуют `atol=1e-10`, `rtol=1e-12`.
- При перехваченной ошибке публикации восстанавливается предыдущий набор затронутых файлов. Маркер `reports/PUBLISH_IN_PROGRESS` запрещает чтение через `RepositoryData` и повторную публикацию при незавершённом обновлении. После аварийного завершения процесса или ошибки восстановления нельзя просто удалить маркер: следует построить и проверить новый отдельный каталог. Это не транзакция файловой системы и не защита произвольных внешних читателей; не запускать обучение одновременно с публикацией.

Полный отчёт, исходные хеши, независимые сверки и регрессионные тесты: `reports/parser_audit/AUDIT_REPORT.md`.
