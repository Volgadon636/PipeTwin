# Резюме встречи с менторами

Источники: расшифровка встречи, сообщения в Telegram, описание кейса, критерии оценивания и материал ПАОТ. При расхождениях приоритет отдан последним уточнениям команды, затем скриншоту Telegram. Дата встречи и состав участников в материалах не указаны.

## Главное

Цель работы — построить прогноз **минимальной остаточной толщины стенки трубопровода** по сегментам, используя данные диагностики и потенциально влияющие на коррозию признаки. Для результата нужна именно **residual wall thickness**; глубину дефекта отдельно прогнозировать не требуется. Практический результат по уточнению команды — выявить критические места трубопроводов среди этих сегментов и сформировать приоритетный список участков для проверки УЗТ по прогнозируемому состоянию на заданную дату.

### Приоритетные уточнения команды и Telegram

- ID относятся к **целым трубопроводам**, а не к отдельным участкам. Полные ID и даты с учетом последнего уточнения команды: **1250022871 — 01.12.2023**, **1250009583 — 01.07.2022**.
- Использовать поле **Distance**; **Distance Raw** не использовать.
- Если аномальное значение сохраняется **3 дня**, его оставляют. Кратковременные выбросы можно фильтровать с учетом физической правдоподобности.
- Осадок можно не учитывать.
- **Rep core / Ripcore** — физико-химические свойства.
- Нужна только **residual wall thickness** — остаточная толщина стенки.
- Материал **«ПАОТ для понимания.pdf»** использован как источник физических факторов и перечня возможных данных; наличие каждого признака в фактической выгрузке необходимо проверить.

## Проверка модели и формат результата

Для каждого из двух указанных трубопроводов нужно получить прогноз на соответствующую дату. Менторы описали валидационную таблицу из трех колонок:

1. ID трубопровода.
2. ID сегмента: положение по дистанции с разбиением на интервалы по **10 м**.
3. Прогноз остаточной толщины стенки.

Формат следует сверить с ПТЗ, в том числе обозначения колонок, единицы измерения и правило нумерации сегментов. Желательно подготовить результат так, чтобы менторам не приходилось вручную сопоставлять таблицы в Excel.

В описании кейса основной показатель организаторов — **квадрат коэффициента корреляции Пирсона r²**, отдельно по каждому кейсу. Это не обязательно то же самое, что коэффициент детерминации R²: рассчитывать и обозначать их раздельно. На встрече дополнительно предложили указать **R², MAE, MAPE и RMSE**. По уточнению команды, «MMP» в расшифровке — ошибка распознавания слова **MAPE** (средняя абсолютная процентная ошибка). Проверку проводить там, где есть фактические измерения на нужную дату. В разговоре неоднозначно обсуждалась принадлежность объекта **1250009583** к train/test; перед оценкой сверить ее по данным и исключить утечку целевых измерений.

## Требования кейса и сдача

Описание кейса уточняет: объект прогноза — **минимальная остаточная толщина в миллиметрах в каждом 10-метровом сегменте на дату T**. Номер `segment_id` — целая часть расстояния от начала трубы в метрах, делённого на 10. Для отрицательных расстояний отдельно согласовать исключение и границы трубы; не включать лишние сегменты.

**Два сценария:**

1. **Между ВТД:** старт — предыдущее ВТД; используются паспорт, профиль, прошлые ВТД, УЗТ и режим. Прогноз — на дату следующего, скрытого ВТД.
2. **От ввода до ВТД:** старт — номинальная толщина при вводе; доступны паспорт, профиль и режим. Единственное оцениваемое ВТД скрыто. Для обучения такого сценария документ предлагает использовать первый ВТД первой трубы. Соответствие каждого ID сценарию нужно проверить в данных.

Оценочное ВТД организаторы не передают. Для собственной проверки использовать только историю, доступную к дате прогноза, и оценить качество по горизонтам; сравнить модель с простыми базовыми подходами. Итоговый r² организаторы считают отдельно для каждого кейса.

**Обязательные материалы:**

- `result.csv`: ровно `id,segment_id,thickness_pred`; толщина в мм, десятичный разделитель — точка. Одна строка на каждый сегмент обеих труб без пропусков и лишних строк. Сверить покрытие с `sample_result.csv` и проверить файл автоматически.
- Воспроизводимый код: GitHub-репозиторий или Jupyter-ноутбук, формирующий `result.csv` из исходных данных; `requirements.txt`, фиксированный random seed, запуск на обычном ноутбуке или в Google Colab.
- README: запуск, назначение этапов и допущения очистки данных.
- Презентация до 10 слайдов; защита 5 минут и 3 минуты на вопросы. Показать данные и очистку, физический смысл признаков, модель, валидацию и базовые подходы, метрики по горизонтам и кейсам, влияющие факторы и ограничения.

В критериях каждый из четырех элементов оценивается в **0–10 баллов**. Дополнительные плюсы: график «прогноз — факт» и профиль толщины, ранжированные 10% наиболее опасных сегментов, интервалы неопределенности и сравнение подходов. Описание кейса называет список опасных сегментов одной из целей, но в составе сдачи и критериях относит его к дополнительным материалам. По последнему уточнению команды список участков для УЗТ включается в планируемый результат проекта.

## Участки для приоритетной проверки УЗТ

Для трубы **1250022871** оценить состояние на **01.12.2023**, для **1250009583** — на **01.07.2022**. Разбить каждую трубу на 10-метровые сегменты, спрогнозировать минимальную остаточную толщину каждого и выделить участки, которые следует проверить в первую очередь. Это даты оцениваемого состояния; отдельный календарный график проведения УЗТ в материалах не задан.

Для понятной привязки участка предлагается отдельная таблица: `id`, дата прогноза, `segment_id`, начало и конец участка в метрах от начала трубы, прогноз минимальной толщины в мм, место в рейтинге и причина приоритета. Для сегмента `k` начало равно `10 × k` м, конец — `10 × (k + 1)` м с ограничением фактической длиной трубы. Например, `segment_id = 12` соответствует участку 120–130 м. Это пример нумерации, а не выявленный опасный участок.

Критерий ранжирования нужно описать явно. Как базовый вариант можно использовать меньшую прогнозируемую остаточную толщину; при разных номинальных толщинах учитывать также степень утонения. Критическая допустимая толщина в предоставленных материалах не задана: рейтинг приоритетов для УЗТ сам по себе не подтверждает достижение аварийного состояния. Список верхних 10% по приоритету соответствует дополнительному результату из критериев; долю и правило отбора следует зафиксировать.

Полный `result.csv` по-прежнему содержит **все сегменты обеих труб** и только три обязательные колонки. Список для УЗТ оформляется отдельно. Конкретные опасные сегменты можно назвать после расчета модели по исходным данным; настоящее резюме фиксирует постановку и договоренности.

## Материал ПАОТ: что проверить в данных

ПАОТ рассматривает коррозию через характеристики трубы, режим, физико-химический состав, обслуживание, окружающую среду и ремонты. В числе потенциальных признаков: возраст, материал, диаметр и номинальная толщина, покрытия и рельеф; расходы, обводненность, давление, температура, скорость и режим течения; pH, минерализация, ионный состав, CO₂, H₂S, O₂ и механические примеси; ингибирование, очистка, ЭХЗ и замены участков. Ремонты могут менять историю деградации участка. Это перечень кандидатов из материала, а не подтверждение их наличия или качества в файлах кейса. Осадок согласно Telegram можно не учитывать.

Источники наблюдений в ПАОТ — ВТД, УЗТ, коррозионный мониторинг, отказы и история ремонтов. Сопоставлять записи по трубе, положению и времени, не используя данные после даты прогноза.

## Данные и предобработка

- **ВТД** дает сведения о дефектах, **УЗ-контроль** — локальные измерения толщины. Оба источника могут служить для оценки фактического состояния; их пространственную и временную привязку необходимо проверить.
- В обсуждении поле остаточной толщины распознано как `ResidualFitness`; точное имя столбца и единицы нужно сверить в исходном файле. `Defect depth` — глубина дефекта относительно номинальной толщины; для целевой переменной использовать остаточную толщину.
- Брать **Distance**. Значение и связь других полей дистанции и ID следует проверять по исходным данным: в разговоре отмечены расхождения и смена ID.
- Отрицательная дистанция не обязательно ошибка: она может относиться к участку перед камерой пуска. Менторы допустили исключение таких участков; выбранное правило нужно зафиксировать.
- Фильтровать физически неправдоподобные значения и кратковременные выбросы, включая аномалии плотности и расхода. Правило трех дней применять к устойчивости наблюдения; саму физическую допустимость и причины аномалии проверять отдельно. Описать используемые фильтры и преобразования.
- В УЗ-данных обсуждался пример толщины **11 мм** при паспортном диапазоне **5–8 мм**. Причина не установлена; такое значение требует проверки. Версия о замере на стыке не подтверждена.
- В данных ВТД обсуждались значения вроде **28,5** и **0,15–0,17**; точное поле, масштаб и единицы необходимо проверить, прежде чем приводить их к одному виду.

## Факторы и источники признаков

- **Techmod** — технологический режим. **Rep core / Ripcore** — физико-химические свойства и данные контроля коррозии. В разговоре упоминались CO₂, минерализация и ПАЖ; фактический состав столбцов следует проверить.
- Узлы контроля коррозии есть лишь на части объектов: прозвучал пример примерно **19 трубопроводов из 1000**. Требуется продумать обоснованный перенос или агрегацию признаков для остальных трубопроводов; в разговоре упоминались медианы. Числа стоит сверить по набору данных.
- Температура влияет на коррозию. Менторы предложили изучить открытые источники и при необходимости построить физически обоснованный признак. Осадок и его защитное действие в текущей постановке можно не учитывать.
- Высотный профиль, уклоны и режим течения потенциально важны: в низких точках может скапливаться вода и возникать застой, а режим потока влияет на распределение фаз. Число Рейнольдса обсуждалось как возможная упрощенная характеристика режима.
- Перепады высоты нужно оценивать вместе с расстоянием между измерениями: соседние записи могут находиться на десятках метров друг от друга.
- Обсуждались внутренняя и внешняя коррозия, влияние состава среды, механических примесей, защиты и ремонтов. Доступность и качество соответствующих признаков нужно проверить до использования.
