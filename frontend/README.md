# PipeTwin — метрики и прогноз толщины

React + Vite + TypeScript + Recharts + Three.js. Рабочая страница с метриками, факторами модели, списком опасных сегментов, валидацией, профилем толщины и экспериментальным 3D-обзором внизу. Только десктоп, от 1280 px. Интерфейс читает пять JSON из `public/data/`; Python и исходные CSV в браузере не используются.

## Установка

Node **24.6.0** указан в `engines` и `.nvmrc`:

```powershell
cd frontend
nvm use 24.6.0
npm install
```

Готовые JSON включены в проект, поэтому для просмотра Python не нужен.

## Экспорт сохранённых результатов

Из корня репозитория, в существующем Python-окружении с pandas и numpy:

```powershell
.\.venv\Scripts\python.exe -m src.export_frontend_data
```

Либо в активированном окружении:

```powershell
python -m src.export_frontend_data
```

Для отдельного окружения зависимости экспортёра указаны в `frontend/requirements.txt`. Из `frontend/` с активированным Python доступна команда `npm run export:data`.

Экспортёр **не обучает модели, не вычисляет метрики и не создаёт новые прогнозы**. Он копирует сохранённые значения, преобразует структуру CSV/JSON для интерфейса, проверяет согласованность `result.csv` и диагностики и сверяет SHA-256 прочитанных источников до и после. Записываются только пять файлов `frontend/public/data/*.json`.

## Запуск и сборка

Из `frontend/`:

```powershell
npm run dev
npm run build
npm run preview
```

Dev-сервер: `http://127.0.0.1:5173`. Сборка: `frontend/dist/`. `base: './'` позволяет размещать статическую сборку в подкаталоге. JSON загружаются относительно базового URL.

## Проверки

Из корня:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s frontend/tests -v
node --experimental-strip-types --test frontend/tests/pipe_data.test.mjs
```

Проверки сверяют экспорт с готовыми источниками, включая сохранённые метрики, прогнозы и рейтинг риска. Строгая проверка TypeScript входит в `npm run build`; Zod проверяет JSON при загрузке. Предусмотрены загрузка, сообщение об ошибке и повторная попытка.

Шесть Node-проверок вспомогательных функций 3D прошли: источники толщины и пропуски, общий диапазон двух труб, цветовая шкала и её границы, цвет отсутствующих данных, ограничение индекса сегмента, переход между приоритетными сегментами без зацикливания. Production-сборка, четыре проверки исходных данных и проверка 3D в браузере также прошли.

## Работа со страницей

Порядок блоков: профиль толщины → опасные сегменты → прогноз–факт на валидации → факторы и сравнение моделей с метриками → экспериментальный 3D-обзор.

В таблице опасных сегментов нажмите номер сегмента или «Подробнее»: под строкой откроются границы участка, прогноз, P10/P90, дата и доступное прошлое ВТД. Повторное нажатие сворачивает карточку. Кнопка «Показать на профиле» выбирает соответствующую трубу и отмечает сегмент на верхнем графике. При смене фильтра, сортировки или страницы карточка закрывается.

## Экспериментальный 3D-обзор

Выберите трубу и режим просмотра:

- **Снаружи:** тяните мышью для вращения, используйте колесо для приближения; нажмите на трубу для выбора сегмента.
- **Внутри:** тяните мышью для осмотра. Нажмите на сцену, затем используйте W/S или стрелки для движения по сегментам. Клавиши работают только при фокусе на сцене.
- Ползунок и кнопки «Сегмент» перемещают по всей длине трубы. Кнопки «К приоритетному» выбирают следующий или предыдущий сегмент из сохранённых 10 %, без перехода через конец трубы. «Автопроход» последовательно меняет сегменты, «Пауза» останавливает движение.

Справа показаны данные выбранного сегмента: координата, прогноз, P10/P90, прошлое ВТД с датой и сохранённый приоритет. Окраску можно переключать между прогнозом и прошлым ВТД. Цветовая шкала общая для двух труб; серый означает отсутствие измерения. Для холодного старта прошлого ВТД нет. Оранжевые кольца обозначают приоритет проверки, а не угол дефекта.

В сцене виден локальный участок до 25 сегментов вокруг выбранного; полоса навигации охватывает всю трубу. Радиусы условны, длина и диаметр показаны в разных масштабах. Это схема распределения минимальной толщины по сегментам, **не восстановленная поверхность с коррозионными ямами**. Режим «внутри/снаружи» меняет камеру и не классифицирует внутреннюю или наружную коррозию. Для достоверной формы повреждений нужны координаты по окружности и геометрия дефектов на нужную дату; историческое поле `Angle` не описывает будущие повреждения.

Сцена использует существующий `profile.json`, не меняет JSON и не пересчитывает прогнозы. Three.js загружается отдельным отложенным модулем при приближении к блоку. За пределами экрана GPU-отрисовка приостанавливается; при смене трубы и удалении сцены освобождаются геометрия, материалы, обработчики и renderer. Если WebGL или модуль недоступен, показывается сообщение, а данные сегментов остаются доступны.

## Структура

- `src/components/` — общие элементы интерфейса.
- `src/sections/` — пять основных блоков и экспериментальный 3D-обзор.
- `src/charts/` — графики Recharts и подсказка с данными сегмента.
- `src/data/schema.ts`, `src/types/` — схемы и выведенные из них типы.
- `src/hooks/` — загрузка и проверка данных.
- `src/utils/` — форматирование и общие константы.
- `src/three/` — 3D-сцена, камера, настройки и функции работы с толщиной.
- `public/data/` — единственный источник чисел для интерфейса.
- `tests/` — сверка JSON с сохранёнными результатами и Node-проверки функций 3D.
