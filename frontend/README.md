# PipeTwin — H18 для S1, H31 для S2

React + Vite + TypeScript + Recharts + Three.js. Страница показывает **финальный
прогноз H18/H31**, его исторические проверки, очередь обследования и отдельно
проверенные эмпирические интервалы. Десктоп от 1280 px. Все числа в браузере
загружаются из пяти JSON в `public/data/`; Python в браузере не запускается.

## Установка и запуск

Из `C:/Program Files/PipeTwin/frontend`:

```powershell
nvm use 24.6.0
npm ci
npm run dev
```

Поддерживается Node **24.6+ в пределах 24.x**, опорная версия указана в `.nvmrc`.
В текущей проверке использован доступный Node **24.22.1**. Уже подготовленные
JSON входят в поставку, поэтому для просмотра страницы Python не нужен.

Адрес: [http://127.0.0.1:5173](http://127.0.0.1:5173).

```powershell
npm run build
npm run preview
```

`build` запускает строгий TypeScript и создаёт `dist/`. Относительный `base: './'`
позволяет размещать сборку в подкаталоге. Открывайте через HTTP-сервер, а не
двойным щелчком по `index.html`: JSON читаются через `fetch`.

## Полученные интервалы

По отдельному запросу выполнен эксперимент `scripts/calibrate_intervals.py`.
Он использует разрешённые исторические данные и реальные реализации H18/H31
из основного проекта, не изменяя их параметры и финальные точечные прогнозы.

| Кейс | Исторические метки | n | Заявленный уровень | Измеренное покрытие | Средняя ширина на проверке |
|---|---|---:|---:|---:|---:|
| S1 · H18 | 06.07.2022, до cutoff S1 | 357 | 80 % | **73,1 %** | 1,379 мм |
| S2 · H31 | 23.09.2018, до cutoff S2 | 372 | 80 % | **83,6 %** | 1,617 мм |

Используется вложенное исключение простых участков. Внешний участок не входит
ни в обучение модели, ни во внутреннюю калибровку. Во внутренних folds
получаются абсолютные ошибки; граница — порядковая статистика с номером
`ceil((n + 1) * 0.8)`. Для финальной трубы радиус берётся из разрешённых OOF
остатков всех исторических участков соответствующего кейса.

Финальные интервалы: `prediction ± radius`, с ограничением `[0; номинал]`.
Радиус S1: **0,846511 мм**, S2: **0,747071 мм**. У каждого из 2000 сегментов
есть нижняя и верхняя границы. Вложенная проверка использует собственные
радиусы каждого внешнего fold, поэтому её средняя ширина отличается от
ширины интервала финальной трубы.

**Для S1 покрытие 80 % не подтвердилось.** Интервалы эмпирические: это не
P10/P90 квантильной модели и не гарантия покрытия скрытого ВТД. В каждом кейсе
доступны три простых участка одной родительской трубы; независимого переноса
между родительскими трубами или проверки целевого будущего нет. Ограничения
показаны под профилем, в карточках валидации и в описании метода.

Артефакты эксперимента включены в `calibration/intervals/`:

- `summary.json`: метод, cutoff, folds, источники, хеши и покрытие;
- `nested_validation.csv`: 729 внешних проверочных прогнозов с границами;
- `target_intervals.csv`: границы для 2000 финальных прогнозов.

## Обновление JSON

Экспортёр расположен **внутри frontend**: `scripts/export_data.py`. Прежняя
команда `python -m src.export_frontend_data` больше не используется: такого
модуля в текущей рабочей копии нет.

Из `frontend/`:

```powershell
npm run export:data
```

Или явно используйте проверенное окружение проекта:

```powershell
$python = 'C:/Users/Администратор/Documents/PipeTwin_s1abc_env/Scripts/python.exe'
& $python -B scripts/export_data.py
```

Экспорт требует только стандартную библиотеку Python. Он не обучает модели,
не рассчитывает прогнозы или метрики. Читаются выбранная версия из
`../experiments/r2_pool/workflow_state.json`, production-артефакты, сохранённая
валидация, `../reports/final_top10_segments.csv`, подготовленная геометрия,
прошлое ВТД и результаты отдельной проверки интервалов.

По умолчанию подготовленные входы читаются из
`../scratch/odo_alignment_verified`. При другой сборке задайте `--data-root`.
Основной README проекта описывает её восстановление из исходных CSV.

Записываются только пять файлов `public/data/*.json`. Их версия схемы — 2;
все имеют один `release_id`. Фронтенд проверяет Zod-схемы, единство версии,
число сегментов и совпадение рейтинга с профилем. При частично обновлённом
наборе показывается ошибка вместо смешения разных прогнозов.

SHA-256 источников проверяются до и после экспорта. Для сохранённого CSV
допускается только техническая замена CRLF на LF при сверке архивного хеша;
численные изменения такой проверкой не допускаются.

## Повторение эксперимента интервалов

Для него нужно окружение основной модели, а не только Python-экспортёр:

```powershell
python -m pip install -r requirements.txt
python scripts/calibrate_intervals.py --output calibration/intervals_replay
python scripts/export_data.py --intervals-root calibration/intervals_replay
```

Или замените `python` на `& $python` из предыдущего примера. Выходная папка
калибровки должна быть новой; исходный эксперимент не перезаписывается.
`npm run calibrate:intervals` использует `calibration/intervals` по умолчанию
и откажется перезаписать уже существующий комплект.

Обучение вспомогательных fold-моделей разрешено только в этом отдельном
offline-эксперименте. Он использует только даты до cutoff каждого кейса и
исключает диагностику целевого S2. Никакой калибровки по ответам 2023 года
для исторического прогноза S2 на 2022 год не выполняется.

## Проверки

Из `frontend/`:

```powershell
python -B -m unittest discover -s tests -v
npm test
npm run build
```

В этой версии пройдены **10 Python-тестов и 10 Node-тестов**, а также TypeScript
и production-сборка. Проверены все 2000 прогнозов и интервалов, 201 приоритет,
согласованность источников, отрицательные/undefined метрики, отсечение дат,
отсутствие внешнего участка во внутренней калибровке и устойчивость интервалов
к изменению его ответов.

У сборки остаются предупреждения стороннего Zod об аннотациях и о размере
JS-чанков. Three.js подключается отдельным отложенным модулем.
Интерактивная проверка текущей версии в браузере не завершена: встроенный
браузер не получил доступ к localhost, а инструмент Windows остановил
управление Firefox из-за отсутствия поддержки проверки URL. Это ограничение
проверки, а не заявленная успешная визуальная проверка.

## Работа со страницей

Порядок блоков сохранён: профиль → очередь 10 % → прогноз–факт → факторы и
сравнение → экспериментальный 3D. Отключённые пользователем шапка и заголовок
страницы не включались.

- В профиле переключайте S1/H18 и S2/H31. Полоса показывает эмпирический
  интервал; под графиком видны фактически измеренное покрытие и ограничения.
- В таблице нажмите сегмент или «Подробнее»: показываются актуальный прогноз,
  границы, координаты и прошлый ВТД. Кнопка «Показать на профиле» выбирает ту
  же трубу и сегмент. Фильтрация, сортировка и пагинация сохранены.
- В валидации доступны три прежних исторических схемы и два отдельных
  эксперимента интервалов. В раскрывающемся блоке есть все профили.
- Числовая важность и SHAP H18/H31 отсутствуют. Раздел факторов показывает
  действительные входы моделей, без выдуманного ранжирования.
- 3D читает тот же профиль и те же интервалы. Навигация, общий диапазон цветов,
  прошлое ВТД, выбор приоритетов и автопроход сохранены. Сцена схематичная:
  цвет означает минимум толщины, а не восстановленную форму будущего дефекта.

Старые `preview.jpg`, `segment-details-preview.jpg` и `pipe-3d-*.jpg` относятся
к прежнему интерфейсу v2 и не являются снимками обновлённого H18/H31.
