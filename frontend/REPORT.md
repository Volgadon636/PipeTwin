# Источники и ограничения страницы метрик

## Принятый объём работы

После уточнения пользователя используются **исключительно готовые метрики и прогнозы**. Обучение CatBoost, получение новых квантильных прогнозов и пересчёт показателей не входят в итоговую реализацию. Код экспортёра не импортирует CatBoost или обучающие модули. Созданные при первоначальной попытке новые модели и результаты удалены; JSON заменены экспортом сохранённых артефактов.

## Переделка в рабочую страницу метрик

По запросу пользователя применён навык `.agents/skills/cleanup-vibe-code/SKILL.md`. До изменений проверены импорты, TypeScript, ссылки на компоненты, переменные окружения и отладочные остатки. TypeScript проходил; сломанных импортов и отладочного кода не было. Используется только стандартная переменная Vite `BASE_URL`; секреты и внешние интеграции не нужны. ESLint в проекте не настроен; дополнительные зависимости для этой переделки не устанавливались.

Удалены рекламный Hero, декоративная схема труб, слоганы, CTA, декоративные номера секций, повторяющиеся пояснения и подвал. В интерфейсе пять блоков: факторы, сравнение подходов, опасные сегменты, валидация, профиль толщины. Сценарный интервал встроен в профиль и таблицу. Метрики доступны сразу на первом экране. Подробности методики свёрнуты в `details`.

Увеличен размер текста, введена спокойная нейтральная палитра, удалена загрузка шрифта Google Fonts. P10 и P90 стали отдельными сортируемыми столбцами. Подсказка для любой точки профиля показывает сегмент, координату, прогноз, P10/P90 и дату прошлого ВТД, если оно есть. Переход из таблицы показывает те же значения для выбранного сегмента.

`HeroSection`, `PipelineDiagram`, `UncertaintySection` удалены после проверки отсутствия потребителей. Неиспользуемые `TOP_FEATURE_COUNT`, `COLORS.ink`, `percent` и прежние CSS-правила удалены. Контракты JSON, источники и Python-экспортёр не менялись: SHA-256 всех пяти JSON совпали до и после изменений. Обучение и пересчёт метрик не запускались.

После переделки прошли TypeScript, production-сборка и четыре проверки сохранённых данных. В браузере проверены фильтр, пагинация, сортировка P90 и сегмента, переход к точке с P10/P90, обе трубы, оба сценария валидации и сравнения. Ошибок или предупреждений в консоли нет. JSON и исходные данные не изменены.

## Что найдено в репозитории

Изучены README, requirements.txt и requirements-ml.txt, `data/`, `processed/`, `src/ml/`, `promts/` (в репозитории именно такое написание), `agent/`, отчёты и manifests в `reports/`, `experiments/ml_baseline/`, `experiments/ml_v2/`, повторные результаты в `scratch/`, документы `docs/model_v2.md`, `docs/ml_model_card.md`. Вне виртуального окружения и зависимостей не найдено сохранённых `.cbm`, `.pkl`, `.joblib` или ноутбуков `.ipynb`. В `catboost_info/` нет пригодного сохранённого результата. Каталог `frontend/` был пуст.

Для навигации по коду использован существующий актуальный CRG MCP граф репозитория; связь `build_training_windows → make_snapshot` подтверждена исходниками. Граф не обновлялся.

Готовые модели проекта — физические C0/M0/M1/M1S, а не итоговая CatBoost. Запрос назвать итоговую модель CatBoost нельзя выполнить достоверно с имеющимися артефактами.

## Метрики: перенесены без пересчёта

`experiments/ml_v2/metrics.json`, раздел `cold_start_pooled`, содержит общую выборку 466 наблюдений и leave-one-pipe-out оценку:

| Модель | MAE, мм | RMSE, мм | Pearson² внутри кампаний |
| --- | ---: | ---: | ---: |
| C0: без утонения | 1.6760944206008583 | 1.799456641880705 | не определён |
| M0: постоянная скорость | 0.432555878354948 | 0.5380332142895434 | не определён |
| M1: физика среды | 0.4289216552371229 | 0.5610891256125352 | не определён |
| M1S: физика и профиль | 0.42889812716839437 | 0.5580843177832749 | 0.016595176852561233 |

Этот Pearson² вычислен в исходном эксперименте после удаления среднего каждой кампании. Это не обычный R² и не метрика скрытого целевого ВТД. Сводного обычного R² для этих строк в источнике нет. В интерфейсе модель v2 выделена как используемая для прогноза, без утверждения о доказанном превосходстве.

Между ВТД: `between_vtd_pooled`, 357 исторических пар, leave-one-pipe-out. C0/M0/M0dense имеют одинаковые MAE 0.49822273660440736 мм, RMSE 0.652255303799292 мм и Pearson² 0.11325940806478503. Эти показатели показаны отдельным переключаемым сценарием; они не смешиваются с холодным стартом.

## Scatter и схема валидации

Готовые построчные пары «факт — прогноз» есть в `experiments/ml_baseline/validation_predictions.csv`, **только для C0**. Для M1S готового файла с такими парами не найдено. Поэтому scatter явно подписан как baseline C0:

- Между ВТД: 561 наблюдение на 06.07.2022, Pearson² 0.06121237593228315, R² −0.5827926087603434, MAE 0.530455466965728 мм, RMSE 0.6778607462675411 мм.
- Холодный старт: 372 наблюдения на 23.09.2018, Pearson² не определён из-за постоянного прогноза, R² −11.599441381367775, MAE 1.878494623655914 мм, RMSE 1.9577943206962618 мм.

Числа взяты из `experiments/ml_baseline/metrics.json`, строки `status=evaluated`, `subset=all`, а не вычислены экспортёром. Для этих временных срезов нет более ранних независимых обучающих групп, поэтому обучаемые модели не имеют допустимых forward-fold оценок. В v2 использованы более слабые ретроспективные leave-one-pipe-out / leave-one-campaign-out проверки; простые участки одного направления не равны независимым направлениям. Случайное разделение соседних сегментов не вводилось.

## Важность факторов

Feature importance и SHAP в проекте не сохранены. Раздел не показывает придуманных весов или столбцов. В JSON указаны `available=false`, `method=null`, пустой массив моделей; в интерфейсе — явное отсутствие числовой важности и перечень физических факторов из модели: температура, обводнённость, скорость смеси, профиль.

Для заполнения числовой диаграммы нужен готовый FI/SHAP артефакт с описанием метода и обучающего среза. Получать его новым расчётом после уточнения пользователя не стали.

## Профиль и прогнозы

Источники: `experiments/ml_v2/result.csv` и `prediction_diagnostics.csv`, ключ `(id, segment_id)`. Экспортёр проверяет совпадение прогнозов этих двух файлов.

| Труба | Сегментов | Длина, м | Дата прогноза |
| --- | ---: | ---: | --- |
| 1250022871 | 525 | 5248.4 | 01.12.2023 |
| 1250009583 | 1475 | 14745.1 | 01.07.2022 |

Позиция — начало сегмента `start_m`, конец — `end_m`; шаг 10 м, конечные сегменты укорочены. Длина берётся из суммы опубликованной сетки, не из количества сегментов × 10.

Линия «прошлое ВТД» использует `last_vtd_thickness_mm`, только если `has_previous_vtd=true`; дата каждого измерения сохраняется как `actual_date`. Четыре сегмента с заимствованной начальной толщиной не выдаются за измеренные. Для холодного старта факт равен `null`. Целевого факта на датах прогнозов нет. Линия не интерполирует пропуски. Прогноз, сценарные границы и опасные точки отображаются для всех 2000 сегментов; Brush позволяет приблизить участок.

## Риск

Готовый `experiments/ml_v2/risk_top_10pct.csv` содержит 201 запись: 53 для трубы 1250022871 и 148 для 1250009583. Экспортёр переносит этот рейтинг, не рассчитывает новый. Его сохранённый критерий: `ceil(0.1 × N)` внутри каждой трубы, сортировка по прогнозной толщине по возрастанию, при равенстве по `segment_id`.

Уровень «проверить в первую очередь» — относительный приоритет инспекции. Данных для нормативных категорий «аварийный/критический», минимально допустимой толщины и вероятности отказа нет. Сортируемая таблица содержит все 201 сегмент, фильтр, страницы и переход к выбранной точке профиля.

## Интервалы и покрытие

Существуют поля `thickness_p10` и `thickness_p90` в готовой диагностике v2:

- холодный старт: диапазон сценариев априорных физических параметров, 243 сценария;
- между ВТД: прогноз плюс квантили изменений в исторических парах.

Это не калиброванные интервалы квантильных CatBoost-моделей. Поэтому таблица и график подписаны как **сценарные границы**; сохранённые числа перенесены без расширения, обрезания или новой калибровки. Готового покрытия по факту на независимой валидации нет: в интерфейсе «Нет данных», JSON `coverage=null`. Для покрытия нужен готовый артефакт, содержащий факт и обе границы на одной отложенной выборке. По уточнению пользователя такой расчёт не выполнялся.

## Файлы и воспроизводимость

`src/export_frontend_data.py` — единственный новый файл вне `frontend/`, предусмотренный исходной задачей. Он записывает только `frontend/public/data/metrics.json`, `feature_importance.json`, `top_risk_segments.json`, `validation.json`, `profile.json`. SHA-256 источников сохранены в `metrics.json → provenance`; `models_trained=false`, `metrics_recomputed=false`. Исходные CSV, модели, эксперименты, отчёты, зависимости и README в корне не меняются. Существовавшие до задачи удаление `processed.zip` и каталог `.agent/` не затрагивались.

## Проверка реализации

Проверено на Node 24.6.0:

- `npm install`: успешно, 159 пакетов, аудит без уязвимостей.
- `npm run dev -- --port 5173 --strictPort`: Vite запустился, HTTP 200.
- `npm run build`: строгая проверка TypeScript и production-сборка прошли. Rollup сообщает о комментариях аннотаций в зависимости Zod и размере общего JS-файла; это предупреждения, не ошибки сборки.
- `python -m unittest discover -s frontend/tests -v`: 4 проверки прошли. Сверены значения метрик, прогнозы, отсутствие выдуманного факта, состав готового рейтинга, отсутствие FI/SHAP и покрытия.
- Браузер: страница загружает JSON; проверены фильтр по трубе, страницы рейтинга, сортировка по сегменту, переход к выбранному сегменту на профиле, обе трубы, переключатели валидации и сравнения моделей. В консоли браузера нет предупреждений или ошибок. Десктопная проверка при CSS-ширине около 1295 px: горизонтального переполнения нет.

Снимок страницы сохранён в `frontend/preview.jpg`. Мобильная адаптация намеренно не добавлялась.
